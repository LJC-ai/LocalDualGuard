# DualGuard-Sec（DualGuard 安全版）

> 面向网络安全实训 / CTF / 渗透测试演练场景的**本地端合规护栏**：在选手终端对违规行为进行计数、警告、72 小时冻结，并对审核策略文件做哈希校验与自动恢复，防止篡改绕过。

DualGuard-Sec 与 DualGuard-Student 共用同一套 `common/` 公共工具库（路径管理、AES+HMAC 加密存储、哈希校验、风控引擎），仅在 `main` 入口注入不同的业务规则与文案，做到"公共库与业务完全解耦"。两套版本的数据目录相互隔离（`sec` / `student`），互不污染违规计数。

---

## 一、项目定位

DualGuard-Sec 是一套**运行在选手 / 学员本机**的轻量合规监护程序，配合赛事或实训平台的审核策略使用：

- **不是**攻击工具、扫描器或漏洞利用框架，本身不产生任何网络流量。
- **不是**远程监控 / 后门，不回传任何数据到外部服务器，所有违规记录仅以 AES-256 加密形式落盘在本机。
- **是**一个"电子监考员"：根据机构下发的 `audit_policy.json` 审核策略，对本地违规动作计数 → 弹窗警告 → 累计达阈值后冻结环境 72 小时，并对策略文件做 SHA256 校验，被篡改时自动从备份恢复。

典型部署形态：赛事主办方在选手平板 / 笔记本上预装 DualGuard-Sec，下发审核策略，开赛即生效。

## 二、使用场景

| 场景 | 说明 |
|------|------|
| 线下 CTF / AWD 比赛 | 在选手终端约束违规操作（如越权访问他人靶机、篡改比赛客户端），违规计数达阈值自动冻结 |
| 网络安全实训机房 | 实训课上对学员本机行为做合规计数，事后可导出加密违规记录复盘 |
| 渗透测试授权演练 | 在**已获书面授权**的封闭靶场内，对红队终端做操作留痕与越界冻结 |
| 内部安全考试 | 防止考生篡改考试客户端、防系统时间回拨绕过计时 |

## 三、核心能力（基于 `common/` 公共库）

- **违规计数 + 72 小时冻结**：单调计数器（`monotonic.state`）防系统时间回拨绕过。
- **AES-256 + HMAC 加密存储**：违规记录（`violations.enc`）防篡改、防读取。
- **审核策略哈希校验 + 自动恢复**：`audit_policy.json` 的预期 SHA256 存于 `audit_policy.sha256`，被篡改时从 `backup/` 自动还原并弹篡改警告。
- **可插拔前置审核 AI**：`pre_audit` 接口允许赛事方注入自定义规则引擎。
- **跨平台**：Windows（平板/笔记本）+ Linux（服务器/实训机）。

数据目录约定（见 `common/paths.py`）：

```
Windows: %PROGRAMDATA%\DualGuard\sec\
Linux  : /var/lib/dualguard/sec/
```

## 六、快速开始

### 6.1 安装（终端用户）

- **Windows**：双击 `DualGuard-Sec-Setup-x.y.z.exe` → 安装向导 → 完成。详见 [docs/packaging.md](docs/packaging.md#windows-exe-安装与卸载)。
- **Linux**：`sudo dpkg -i dualguard-sec_x.y.z_amd64.deb` → 服务自启。详见 [docs/packaging.md](docs/packaging.md#linux-deb-安装与卸载)。

### 6.2 运行

安装后程序以后台服务 / 托盘程序形式常驻，读取 `config.yaml` 与审核策略 `audit_policy.json` 生效。配置说明见 [config.yaml](config.yaml)。

### 6.3 开发者：从源码运行

```bash
# 仓库根目录
python -m pip install -r requirements.txt
# 以 sec 版本启动
python -m DualGuard_Sec.main
```
